## [Unreleased]

### ✨ Features
- **Dhizuku Compat add-on** — Optional small APK (on each GitHub release) that lets apps using an older Dhizuku library, like Amarok 0.10.1, connect to Shizuku+. Only needed if you use Dhizuku Mode without the real Dhizuku app, and can't be installed alongside it.
- **Customizable Service Doctor repairs** — Choose exactly which repairs to run with checkboxes, with selections remembered for future manual and background fixes ([#656](https://github.com/thejaustin/ShizukuPlus/issues/656)).
- **Service Doctor start repairs** — Automatically offers TCP mode when port discovery times out, and generates fresh ADB keys when pairing stalls ([#656](https://github.com/thejaustin/ShizukuPlus/issues/656)).
- **App access safety checks** — Requests now display installation source, install date, and certificates, with optional VirusTotal and Pithus hash lookups in Settings.
- **Enhanced navigation bar** — Reorder tabs with drag-and-drop, choose between Floating, Docked, Compact, and Capsule styles, and customize directly from Home Edit Mode.
- **Smart toolbar integration** — Settings button in the top app bar automatically hides when Settings is pinned to the navigation bar (configurable in Developer Options).
- **Per-app API scopes** — Granularly restrict what authorized apps can access (shell, package manager, activity manager, app ops, system settings) instead of all-or-nothing permissions ([#645](https://github.com/thejaustin/ShizukuPlus/issues/645)).
- **Batch app management** — Grant, revoke, or hide multiple authorized apps simultaneously ([#1](https://github.com/thejaustin/ShizukuPlus/issues/1)).
- **Unified problem notifications** — Active service problems and quick fixes update in place in a single notification instead of piling up.
- **Home screen layout lock** — Prevent accidental drag-and-drop card rearranging via Appearance settings ([#590](https://github.com/thejaustin/ShizukuPlus/issues/590)).
- **Quick app sorting** — Dedicated sort chip in the filter row lets you instantly sort by name, install date, update date, or granted status.
- **Trusted Wi-Fi picker** — Select saved networks directly from a list for Wireless ADB protection without needing location permission.
- **Restore confirmation** — Settings backups discovered on first launch ask before applying, with security-sensitive options requiring explicit confirmation.
- **Optional setting disabling** — Developer option to bypass dependency checks and lockouts so all settings remain enabled and configurable.
- **Fluid Home card dragging** — Dynamic overlap-area and center-containment target resolution, card-wide drag touches in edit mode, and smooth edge auto-scrolling.

### 🔒 Security & Privacy
- **Protected Plus APIs** — Sensitive device control and private app data APIs are restricted to user-confirmed apps in Developer options.
- **Persistent debugging warning** — Alerts for Wireless ADB remaining active on untrusted networks always display regardless of notification levels.
- **Client key authentication** — Local ADB connections require explicit key verification with matching fingerprint prompts.
- **Per-app scope enforcement** — Command scoping blocks shell quoting tricks, background helper leaks, and chained command bypasses ([#648](https://github.com/thejaustin/ShizukuPlus/issues/648)).
- **Private crash reports** — Packages, IPs, network names, and command parameters are scrubbed from crash reports and error logs.
- **Secure backups** — Sensitive scanner API keys, hidden app lists, and private ADB keys are excluded from unencrypted device transfers and cloud backups.
- **Safe clipboard copying** — Sensitive script outputs, logs, and crash reports are marked private to prevent display in Android clipboard previews.

## [v13.7.0-p1 — Major Stable Release] - 2026-10-25

### 🌟 Highlights

- **Material 3 Expressive look, done properly** — springy motion that follows the Expressive animations switch, a full corner scale that every Shape Style (and Compose screens) now share, a real type scale for Bold typography, opt-in full colour schemes for accents, morphing expressive icon shapes, and connected toggle-button groups in Settings.
- **Easier wireless pairing** — the pairing code entry pops up over Settings again, the pairing screen shows live status with a Start button, and an opt-in helper can fill in the code for you.
- **You decide what gets privileged access** — crash reports, automation apps (Tasker/Locale) and the AICore+ accessibility service now wait for your consent, and the server only trusts a second manager signed like this one.
- **Faster server** — apps get their Shizuku connection about 3x sooner after the server starts, and the server needs much less memory.
- **Rebuilt Icon Studio, System Hub and Activity Log** — plus a new Experimental features screen and an optional floating navigation bar.

### 🔒 Privacy & Security
- **Crash reports are opt-in** — nothing is sent until you say yes (asked once after setup; switch in Settings → Advanced & diagnostics). Reports no longer carry IP/MAC addresses, Wi-Fi names, emails or screenshots.
- **Automation apps need permission** — Tasker/Locale can start or stop Shizuku+ only with "Allow automation apps" on. It stays on after an update and is off for new installs.
- **AICore+ accessibility service is never switched on behind your back** — its self-repair only runs once you've enabled the service yourself in Android's settings.
- **Only a manager signed like this one is trusted** — the side-by-side Plus/Drop-In manager and the manager-only grants were decided by package name, so another app using that name could get them. Root apps are no longer granted automatically, and grants Shizuku+ made are taken back when you turn the feature off.
- **Shizuku+ no longer grants itself extra access** — on every start the server used to switch on 11 app permissions for the app by internal number, including drawing over other apps, all-files access and installing apps, and those numbers mean different things on different Android versions. It now only allows what the app uses (usage access for automation, exact alarms for the Watchdog), by name. Battery and Doze exemption stays with Device hardening & keepalive. Permissions already granted on your device are left as they are.
- **Safer defaults for new installs** — TCP mode starts off, and root-bridge features stay off on the server until your settings reach it.
- **Imported settings never switch privileged features on** — restoring a backup asks before it turns on anything that grants access.

### 🐞 Crash reports
- **Pick which crashes go into a manual crash report** — Shizuku+ now keeps its last 10 crashes, and Developer options → Manual Crash Report asks which to include (the newest is pre-selected) before copying or sharing the report. ([#628](https://github.com/thejaustin/ShizukuPlus/issues/628))

### 🔌 Pairing & Connection
- **Pairing code entry pops up over Settings again** — the "pairing service found" notification alerts as a heads-up instead of updating silently, so you no longer need to pull down the shade mid-pairing. Tapping it no longer opens a dialog that could close Android's pairing screen.
- **Live pairing status** — the pairing screen shows what's happening (searching, found, pairing, paired, failed and why) and gives you a Start button once paired. If Shizuku+ can write secure settings, it starts the service right after pairing.
- **Optional "Fill in the code for me"** — an opt-in helper that types the 6-digit code into Android's pairing dialog. It only works inside the Settings app.
- **rish and the SU Bridge work again on release builds** — they stopped with "VerifyError … not instanceof Throwable" because the app's shortened internal class names collided with those in the rish file. No need to export rish again. ([#626](https://github.com/thejaustin/ShizukuPlus/issues/626))
- **MT Manager 2.14 and other apps with the old rish loader now work** — they looked for upstream Shizuku's class name and native library. To answer them in time, Shizuku+ can keep itself running while the server is up (Settings → Startup & behavior; on by default for the Drop-In version).

- **Lower server memory** — the server maps its code straight from the APK instead of unpacking it into memory (about 56 MB less on a test device), and Plus services are created only when first used. The download is about 4.6 MB larger as a result.

### 🛠️ Developer & Technical Changelog

### 🐛 Bug Fixes

#### Server / Binder
- **Fixed permission changes lost when the server is stopped or restarted soon after** — the server wrote `shizuku.json` 10 s after a change, and `exit()` called `System.exit(0)` without writing a change still waiting, so a grant, revoke or removal followed within 10 s by Stop, a restart from the app (the starter kills the running server) or a crash was gone at the next start. A change the user makes is now written at once on the worker thread; start-up's bulk reconcile still writes once after 10 s. `exit()`, the uncaught-exception handler and the manager-uninstalled exit write any change still waiting first, waiting at most 2 s for it, and the config is serialized under the manager's lock so the worker's write and an exit's write reach the disk in order.
- **Fixed a permission change being lost when saving the config fails** — a failed write of `shizuku.json` (a full disk, say) was logged and dropped: nothing tried it again, and the change lived only in memory until the next restart lost it. `AtomicFile.finishWrite` also only logs a failed sync, close or rename, so some failed saves were not even noticed. The server now syncs the data itself, checks after `finishWrite` that the file holds as many bytes as were written, and on a failure keeps the change waiting and tries again after 1, 2, 4 and 8 s, then every 10 s; a change made meanwhile is still written at once, and Stop, a restart or a crash tries the save once more and logs an error if the change is still not saved.
- **Fixed 'Preference already has a SummaryProvider set' crash in Settings on Android 16/17** — Calling `.summary = ...` or `.setSummary(...)` on preferences with active summary providers threw `IllegalStateException`. Added `Preference.setCustomSummary()` extension across `BaseSettingsFragment` to safely clear `summaryProvider = null` before assignment and guarded `IntegerSimpleMenuPreference.setSummary()`. ([#587](https://github.com/thejaustin/ShizukuPlus/issues/587))
- **Fixed 'Padding must be non-negative' crash in Settings on font/display-size changes (Android 16)** — `SettingsScreen` uses `LargeTopAppBar` with `exitUntilCollapsedScrollBehavior`. The `LargeTopAppBar` updates `heightOffsetLimit` in its layout pass (after composition), so there is a one-frame window where a previously scrolled `heightOffset` is below the new limit. The stale offset causes Scaffold to report a negative top padding, throwing `IllegalArgumentException: Padding must be non-negative`. Fix: added `LaunchedEffect(scrollBehavior.state.heightOffsetLimit)` that re-coerces `heightOffset` via the setter (which enforces `[heightOffsetLimit, 0f]`) whenever the limit changes — same pattern as `HomeScreen.kt:87`. Added belt-and-suspenders `coerceAtLeast(0.dp)` on all three `innerPadding` padding call-sites in `SettingsScreen`. ([#569](https://github.com/thejaustin/ShizukuPlus/issues/569))
- **Fixed manual `pm revoke` being silently overridden on every server restart** — `migratePermissionGrants()` was designed as a one-time backfill for apps that had a ConfigManager authorization entry but no OS-level runtime permission grant (a side-effect of a silent bug in versions prior to 2026-07-19). Running it unconditionally on startup meant that any permission manually revoked with `pm revoke <pkg> af.shizuku.plus.permission.API_V23` was re-granted moments later when the server started. The migration is now gated by a `permGrantMigrationDone` flag persisted in `shizuku.json`; it runs exactly once, marks the flag, and skips on all subsequent starts. New grants continue to be issued at connect time in `attachApplication`. ([#568](https://github.com/thejaustin/ShizukuPlus/issues/568))
- **Fixed Installer X Revived, Universal Installer X, Total Commander, and all stock `dev.rikka.shizuku:api` apps broken after r2739** — root cause: `LegacyShizukuBinderProxy` subtracted 1 from every transaction code for apps that declared `moe.shizuku.manager.permission.API_V23`, but stock-API clients already send the wire codes the generated stub expects (`= N` means `FIRST_CALL_TRANSACTION + N`), so e.g. `addUserService` (wire 12) arrived as `setSystemProperty` (wire 11). The proxy and `isLegacyOriginalShizukuApp()` are now **fully removed** — every client gets the real binder. Three wire codes that the hand-written switch in `Service.onTransact()` mis-numbers are now intercepted first in `ShizukuService.onTransact()`, decided by the parcel shape, never by caller identity: `getVersion` (code 3), `attachApplication(IBinder, String)` from API ≤ 12 (code 14), and `shouldShowRequestPermissionRationale` when the parcel carries no arguments (code 17). ([#566](https://github.com/thejaustin/ShizukuPlus/issues/566), [#567](https://github.com/thejaustin/ShizukuPlus/issues/567))
- **Fixed System Hub metrics remaining empty (all 0s) on startup** — When the server started without an immediate manager settings push, `isFeatureEnabled("ai_core_plus")` defaulted to false, returning a null `aiCorePlus` extension and causing `ServerMetricsScreen` and `ServerMetricsFragment` to display zeros for uptime, memory, and client count. Defaulted `ai_core_plus` to true alongside other core bridge features in `ShizukuService.java`, added throttled manager appId re-resolution in `checkCallerPermission()`, and wired auto-sync retries in the metrics screens. ([#597](https://github.com/thejaustin/ShizukuPlus/issues/597))

#### ADB & Connectivity
- **Adaptive Multi-Interface & IPv6 Connection** — `AdbPortProber` now resolves all candidate network host addresses (`preferredHost`, `127.0.0.1`, `::1`, and active local interface addresses like `wlan0`). Parallel probing across candidates cuts latency to ~150 ms. `AdbStarter.connectAdaptive` dynamically attempts connections across all candidate hosts with exponential backoff on refusal.
- **Adaptive Pairing Socket Connection** — `AdbPairingClient` now probes candidate hosts adaptively during TLS setup, eliminating pairing hangs on OEM skins (MagicOS, HyperOS, OxygenOS) where pairing binds to interface IPs rather than loopback.
- **A_AUTH handling after A_STLS** — `AdbClient.connect` now handles `A_AUTH` tokens/signatures received after TLS handshake instead of failing with `not A_CNXN`.
- **mDNS Resolution Hardening** — `AdbMdns` now strips IPv6 zone identifiers (`%zone`), safely handles null service hosts, verifies all active network interfaces for bound services, and performs non-blocking TCP verification for `TLS_CONNECT` services.
- **LAN Reconnect on Offline / Local Wi-Fi** — `ReconnectTrigger` no longer requires public `NET_CAPABILITY_INTERNET`, allowing Wireless Debugging to reconnect on local development LANs while preserving network-trust policy checks.
- **Eliminated Stale Port Reboot Backoff** — `AdbStartWorker` verifies `isPortOpen(savedPort, 200)` and immediately initiates mDNS discovery on attempt 0 if the port is closed, avoiding 15–30s WorkManager backoffs.
- **Fixed duplicate "Service started" activity log entries** — every ADB start path in `AdbStartWorker` called `ActivityLogManager.log()` after `AdbStarter.startAdb()` had already logged its own entry, resulting in two identical or near-identical lines per start (visible in the History tab). `startAdb()` now accepts an optional `activityLogMessage` so each call site provides its own contextual description ("direct TCP port", "force_start_wadb probe", etc.) as a single entry; the redundant worker-level log is removed.

### 🐛 Bug Fixes

#### Server / Service
- **Fixed server crashing on Android 9 (API 28) with `NoClassDefFoundError: android/provider/DeviceConfig`** — `disablePhantomProcessKiller()` had a direct static-call reference to `DeviceConfig.setProperty()` (API 29+). ART on API 28 resolves all class references during bytecode verification, before the `SDK_INT < 31` guard can execute; R8 inlining made it worse by placing the reference in `<init>`. Changed the call to `Class.forName()` reflection, eliminating the direct class reference entirely. `ClassNotFoundException` from `Class.forName` extends `Exception` and is caught; `NoClassDefFoundError` (which was thrown) extends `Error` and was not. ([#527](https://github.com/thejaustin/ShizukuPlus/issues/527))
- **Fixed Shadow Binder `getPackageUid()` returning 0 (root UID) for hidden packages** instead of -1 (Android's "package not found" sentinel) — apps checking whether a hidden package is installed received UID 0 (system/root) and treated it as installed, or had completely wrong assumptions about the owner. ([#444](https://github.com/thejaustin/ShizukuPlus/issues/444))
- **Fixed Shadow Binder IPackageManager intercepts matching unrelated Binder calls** when the `TRANSACTION_*` field initialization via reflection fails (rare on unusual vendor ROMs) — the -1 sentinel value used as "not initialized" could accidentally match valid transaction codes on those devices, intercepting calls from unrelated apps and returning spoofed data.
- **Re-verified the shell/rish consent re-implementation (`32382e89`) across every client type** — rish/shell, root/su, normal app clients, and Dhizuku clients each go through their own already-uid-verified path; no remaining spoofing or persistence gap found. Fixes "Allow always" not persisting ([#420](https://github.com/thejaustin/ShizukuPlus/issues/420)) and the underlying re-implementation request ([#416](https://github.com/thejaustin/ShizukuPlus/issues/416)).
- Fixed a stale code comment in `ShizukuService.checkCallerPermission()` still describing the deleted notification-based shell-consent flow.
- **Fixed the build.prop Redirection module silently doing nothing** — it staged its writable shadow copies under `/data/adb/shizuku/` (0700 root), which the server (shell UID 2000) can't create or write, so the `mkdirs`/copy failed *and* the command path was still rewritten to that dead location. Shadows now stage in `/data/local/tmp/shizuku_proxy`, and the original path is only rewritten once the writable copy actually exists. ([`ed188594`](https://github.com/thejaustin/ShizukuPlus/commit/ed188594))
- **Fixed Firewall Success Mocking never applying a real rule for per-app blocks** — one of three duplicate `iptables --uid-owner` handlers passed `POLICY_ALLOW_METERED_BACKGROUND` (value 4) to `setUidPolicy`, which is the *opposite* of a restriction and throws `IllegalArgumentException` on modern AOSP, so no policy was ever set. The three handlers are consolidated into a single `mapIptablesToNetworkPolicy` helper using the correct reject value. ([`ed188594`](https://github.com/thejaustin/ShizukuPlus/commit/ed188594))

#### Plus Feature APIs (Device Control, App Backup, Storage Proxy)
Hardening pass on the newly-added privileged Binder services, which are reachable by untrusted third-party callers across the Shizuku IPC boundary. Found via multi-agent static analysis, not field reports.
- **Fixed a Java compile error that broke the build** — `ShizukuSettings` declared `isStealthModeEnabled()`/`setStealthModeEnabled()` twice (a stale May copy plus the current one wired into `syncAllPlusFeaturesToServer`); duplicate methods in the same class don't compile, so `HEAD` did not build. Removed the stale copy.
- **Added package-name validation on every `run-as`-backed data path** — `BackupRestorePlus` (external/OBB backup + restore) and `StorageProxy` (`tarDirectory`/`restoreTarDirectory`) previously passed the caller-supplied package straight to `run-as` after only a null/blank check, letting a caller target an arbitrary *debuggable* app's private data. All now gate on a shared `InputValidationUtils.isValidPackageName` whitelist (`[a-zA-Z]...` dotted segments) that rejects path traversal, shell metacharacters, and option injection.
- **Removed `edl` (Emergency Download) from the reboot whitelist** — `DeviceControlPlus.reboot()` accepted `edl`, which drops the device into a vendor flash mode most users can't exit without a PC + firmware. Exposing that across an untrusted Binder boundary is a bricking foot-gun; the whitelist is now `recovery`/`bootloader`/`fastboot`/`quiescent`.
- **Fixed `clearAppData` reporting success even when it failed** — it awaited the `IPackageDataObserver` callback but ignored the `succeeded` argument and returned `true` after the timeout regardless. It now returns `true` only if the observer actually reported success in time, otherwise falls through to the `pm clear` fallback instead of lying to the caller.
- **Fixed potential pipe-buffer deadlocks in tar streaming** — the backup `pipe()` and both restore extractors could hang if a chatty child (verbose `tar` warnings) filled its stderr/stdout pipe buffer while the parent was blocked copying the other stream. Added a `drainQuietly` daemon-thread drain on the non-data stream.

#### Manager App (UI)
- **Fixed home screen header bar (stop/settings/help buttons) obscured by the status bar on Android 17+** — the topBar `Surface` used `windowInsetsPadding(WindowInsets.statusBars)` inside the Scaffold's `topBar` slot. Compose Material3 1.4+ consumes `contentWindowInsets` before composing all Scaffold slots including `topBar`, so `WindowInsets.statusBars` inside that slot resolves to 0 and the action icons render behind the status bar. Fixed by using explicit `padding(top = statusBarPadding)` where `statusBarPadding` is captured before the Scaffold (from the root composition's unmodified insets). ([#528](https://github.com/thejaustin/ShizukuPlus/issues/528))
- **Fixed manager crash when opening Permission Manager or Device Control via Explode transition on Android 16+** — `PermissionManagerActivity`, `DeviceControlActivity`, and `SystemHubActivity` all called `WindowCompat.setDecorFitsSystemWindows(window, false)` after `AppActivity.onCreate()` had already called `enableEdgeToEdge()` (which sets the same flag). The conflicting calls produced inconsistent window state during the Explode enter/exit transition, crashing on API 36+. Removed the redundant calls and left explanatory comments. ([#529](https://github.com/thejaustin/ShizukuPlus/issues/529))
- **Fixed AMOLED+ mode not applying in Permission Manager, Device Control, and System Hub screens** — those three activities called `AppTheme()` without the `isAmoledPlus` parameter, so AMOLED+ rendered grey instead of pure black on those screens.
- **Fixed monochrome launcher icon rendering as a sparse outlined ring** under Pixel Launcher's "minimal icons" / themed-icon mode — the monochrome drawable used a stroke-only hexagon path; the single tint color Android applies in monochrome mode turned it into a thin outline. Replaced with a filled hexagon silhouette so the icon renders as a solid, legible shape. ([#530](https://github.com/thejaustin/ShizukuPlus/issues/530))
- **Settings scroll-snap uses `spring(DampingRatioNoBouncy, StiffnessMedium)`** — the snap animation that flicks the collapsing settings/home header fully open or closed now uses a well-tuned stable spring; replaced the M3E `motionScheme.defaultSpatialSpec()` call which was `@InternalComposeApi` in Material3 1.4.0 stable and caused compile errors in external modules.
- **Fixed AMOLED mode showing grey search menu and surfaces** — all six surface-container tone-scale tokens (`colorSurfaceContainer`, `High`, `Highest`, `Low`, `Lowest`, `Dim`) are now forced to pure `#000000` in both `ThemeOverlay.Black` (XML View system) and `AppTheme.kt` (Compose). Previously near-black values like `#0D0D0D` and `#111111` were visibly grey on high-contrast OLED panels, causing the SearchBar suggestion pane, settings-search card header, and home screen cards to stand out against the pure-black background. ([#496](https://github.com/thejaustin/ShizukuPlus/issues/496))
- **Fixed Start on Boot getting silently re-enabled** after a Samsung One UI backup/restore or app-data partial clear — `syncStartOnBootDefaultIfNeeded()` previously called `setStartOnBoot(true)` unconditionally whenever the migration flag was missing, overwriting the user's explicit "off" preference. It now reads `getComponentEnabledSetting()` first and only promotes `DEFAULT → ENABLED`; an already-`DISABLED` component is left alone. ([#516](https://github.com/thejaustin/ShizukuPlus/issues/516))
- **Fixed AMOLED home screen cards showing dark grey instead of near-black** — `ThemeOverlay.Black` set `colorSurfaceContainerHigh` to `?colorSurfaceContainer`, but `colorSurfaceContainer` was not declared in that overlay, so the `?attr` reference resolved to the base M3 dark palette value (~`#1D1D22`) rather than near-black. All six surface/container tone-scale tokens are now pinned explicitly in the overlay (`colorSurfaceContainer = #0A0A0A`, `High = #0D0D0D`, `Highest = #111111`), matching the corresponding values in `AppTheme.kt`'s `colorScheme.copy()` so XML View and Compose surfaces stay consistent. Affects home cards, the settings-search card header, and the SearchBar suggestion pane. Continued follow-up to ([#496](https://github.com/thejaustin/ShizukuPlus/issues/496)).
- **Fixed settings dropdown categories re-showing hidden items after a collapse+expand cycle** — preferences hidden conditionally via direct `isVisible = false` (root-mode-only `tcp_mode`/`tcp_port` in Behavior settings; `icon_color_mode` for non-Two-Tone icon styles; `edge_to_edge` on API 35+; `blur_ui` on API < S) were not tracked in `CollapsiblePreferenceCategory.unavailableChildKeys`, so `updateChildren()` on the next expand/collapse cycle restored them. All fragment-level conditional hides are now routed through `setChildAvailable()`. Also added an animation guard (`isAnimating`) to `CollapsiblePreferenceCategory` that blocks fast double-taps from flipping the arrow mid-animation, and cancels any running animator before syncing rotation state on ViewHolder rebind.
- **Fixed Shizuku+ failing to start on Android 17 QPR1 (API 37)** — Google began redacting `Settings.Global.ADB_ENABLED` to `0` for third-party apps in this release, causing every ADB-enabled check to report "USB debugging not enabled" even when it was. `EnvironmentUtils.isAdbEnabled()` now returns `true` on API 37+ when the setting reads 0, matching the approach taken in the upstream Shizuku fork. Fixes all four callsites: `AdbStarter.stopTcp`, `StartWirelessAdbViewHolder` button handler, `SettingsHelper.launchOrHighlightWirelessDebugging`, and `AdbStartWorker` boot delay. ([#508](https://github.com/thejaustin/ShizukuPlus/issues/508))
- **Fixed off-main-thread Compose state mutation in the Device Control screen** — `LaunchedEffect` read 16 device values on `Dispatchers.IO` and wrote them straight into Compose state from that background thread. Values are now collected into locals off-main and applied inside a `Dispatchers.Main` block (with `isLoading` reset on Main too), per the project's main-thread state convention.
- **Fixed compile error in `PermissionManagerScreen.kt`** — `return@onToggle` inside the `onToggle` lambda is an unresolved label in Kotlin 2.2.x (stricter label resolution for non-inline function parameters). Replaced the early-return pattern with an explicit `if (app != null)` guard, which is semantically identical.

Removed `@OptIn(ExperimentalMaterial3ExpressiveApi::class)` annotations and replaced `MotionScheme.expressive()` / `motionScheme.defaultSpatialSpec()` calls with stable equivalents (`AppTheme.kt`, `HomeScreen.kt`, `SettingsScreen.kt`).
- **Fixed `<br>` XML well-formedness error in `values-pt-rBR/strings.xml`** — the `dialog_adb_wifi_disconnected_warning` translation used a bare `<br>` tag outside a CDATA section, causing `mergeResources` to fail. Wrapped in `<![CDATA[...]]>` matching the English original.

### ✨ Enhancements

#### Server / Service (Root Compatibility)
- **SU Bridge now performs real framework operations instead of only mocking success**, with a graceful fallback to mocked success only when the real operation genuinely can't run at shell UID:
  - **`iptables --uid-owner` → real per-app network restriction.** Maps to `INetworkPolicyManager.setUidPolicy` (metered-background reject) *stacked with* the `cmd netpolicy` data-saver blacklist for a broader per-UID block, instead of pretending the kernel netfilter rule succeeded. ([`ed188594`](https://github.com/thejaustin/ShizukuPlus/commit/ed188594))
  - **Magisk `resetprop` → real `SystemProperties` set/read.** `resetprop <name> <value>` applies the property (visible in real `getprop`) and `resetprop <name>` returns the live value; deletes and read-only/SELinux-blocked props fall back to mocked success. ([`ed188594`](https://github.com/thejaustin/ShizukuPlus/commit/ed188594))
  - **`chmod`/`chown` attempt the real operation first.** Targets the server can actually modify (app data, `/data/local/tmp`, `/sdcard`) are changed for real; only privileged targets that need root fall back to mocked success so callers don't error out. ([`ed188594`](https://github.com/thejaustin/ShizukuPlus/commit/ed188594))
- **`toybox`/`toolbox` multiplexer calls are now unpacked like `busybox`** — applets invoked as `toybox mount …` / `toolbox iptables …` (the modern AOSP default) now hit the same interception hooks as when the applet is called directly, instead of bypassing them. Unlike busybox, no fake version string is emitted since these are the real system binaries.

#### Home Screen
- **Replaced fake one-handed offset with an authentic collapsing header** — the previous implementation pushed content down by 38% screen height using an artificial spacer with a decorative pill handle, which felt disconnected and broken: the blank gap had no visual relationship to the app bar, and the title never moved to center. Replaced with a proper Samsung One UI–style collapsing `Surface` header where the viewing area **is** the expanded app bar. The title now interpolates from center (expanded, 32/28sp ExtraBold) → start (collapsed, 20sp) using `BiasAlignment`, driven by a real `TopAppBarState` limit calculated from screen height. A hairline divider fades in at the bottom edge when fully collapsed. No fake spacers or pill handles.

The single largest root cause behind "Shizuku+ not detected" reports across this project's history. Affected Morphe, InstallerX Revived, Droid-ify, ObtainX, Obtainium, MT Manager, Termux `rish`, and others. (`8fbe5e47`, [#406](https://github.com/thejaustin/ShizukuPlus/issues/406))

Fixed by force-stopping the app on a denied→granted transition, so its next launch gets a fresh handshake — mirroring the mechanism the revoke path already used for the identical reason.
