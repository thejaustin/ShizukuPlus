# 知识库与故障排查

这里整理 Shizuku+ 常见问题、排查步骤和行为说明。

## 连接与启动服务

### Shizuku+ 显示“服务未及时启动”

这表示服务已经通过 ADB 启动，但特权 Binder 没有在 30 秒内注册。常见原因包括：

- 连接过程中无线调试被系统关闭，例如锁屏或断开 Wi-Fi。
- 设备刚启动时有其他进程占用或竞争 ADB 端口。

处理步骤：

1. 在错误对话框点击“重试”。大多数临时问题会在第二次连接时恢复。
2. 如果持续失败，打开“开发者选项 -> 无线调试”，确认无线调试仍然开启。
3. 检查防火墙、VPN、广告拦截器等是否限制了本地回环流量。

### 无法连接到无线调试服务

Shizuku+ 无法访问 `127.0.0.1` 上的 ADB 端口。最常见原因是网络过滤应用拦截了本地回环连接。

处理步骤：

1. 打开防火墙、VPN 或广告拦截器设置。
2. 将 Shizuku+ 加入允许列表，标准包名为 `af.shizuku.plus.api`。
3. 回到 Shizuku+ 再次点击“启动”。

### 连接屏幕里出现 Java 异常或奇怪代码

旧版本会在连接失败时显示原始异常栈，例如 `java.util.concurrent.TimeoutException`。这容易被误解为脚本或代码错误。

新版已经改为普通语言错误对话框，并提供“重试”按钮。预期内的连接失败不会再把堆栈直接显示给普通用户。

### 连接终端打开后没有任何反应

终端会等待窗口获得焦点后再开始连接。如果终端出现但一直没有日志：

- 确认该窗口确实在前台，不在分屏、悬浮窗或失焦状态。
- 如果端口显示为 `0`，说明端口解析失败。请回到主页，确认无线调试开启后再次启动。

### 连接成功后终端立即关闭

这是正常行为。服务确认运行后，终端会立即关闭，让你尽快回到主界面。连接耗时会在关闭前记录。如果需要查看过程，请到“设置 -> 活动日志”。

### SSL 握手失败 / ADB 密钥损坏

这通常发生在应用更新后 ADB 密钥变化，或设备执行过类似恢复出厂设置的操作。错误对话框会提供跳转到开发者选项的按钮。

处理步骤：

1. 点击错误对话框里的“前往开发者选项”。
2. 在开发者选项中点击“撤销 USB 调试授权”。
3. 回到 Shizuku+ 重新配对，然后再次启动。

### Shizuku 无法开机自启动

开机自启动需要 `WRITE_SECURE_SETTINGS` 权限，该权限必须通过 ADB 授予。如果权限缺失，应用会显示持久通知并提供帮助链接。

请根据安装的构建运行对应命令：

```bash
# Shizuku+ 标准构建
adb shell pm grant af.shizuku.plus.api android.permission.WRITE_SECURE_SETTINGS

# Shizuku+ Drop-In 构建（使用原 Shizuku 包名）
adb shell pm grant moe.shizuku.privileged.api android.permission.WRITE_SECURE_SETTINGS
```

如果看到 `Failure [package not found]`，说明你安装的是另一个构建。可以运行 `adb shell pm list packages | grep shizuku` 确认包名。

同时建议在系统设置中关闭 Shizuku+ 的电池优化。三星 One UI、MIUI/HyperOS、ColorOS 等系统的后台限制尤其激进。

### 开机自启动连接很慢

首次安装后第一次开机，后台 worker 需要通过 mDNS 查找无线调试端口，最多等待 15 秒。第一次成功后端口会被记住，之后会优先尝试保存的端口，连接会更快。

## Watchdog

### Shizuku 一直随机停止

请启用“设置 -> 开机启动与 Watchdog”里的 Watchdog。

启用后，Watchdog 会实时监听服务状态。如果服务崩溃，会按指数退避自动重启：5 秒、10 秒、20 秒，最高间隔 5 分钟，以避免在持续故障时反复冲击系统。

每次崩溃和重启都会写入“活动日志”，你可以看到发生时间和重启次数。

### 反复收到 Watchdog 崩溃通知

如果 Watchdog 通知频繁出现，通常说明服务被系统后台管理杀死，而不一定是 Shizuku+ 自身崩溃。常见场景包括：

- 三星 One UI 的自动拦截器、内存优化或休眠应用。
- MIUI/HyperOS 的后台进程清理。
- OPPO/ColorOS 的电池守护或后台限制。

处理步骤：

1. 在系统设置中关闭 Shizuku+ 的电池优化。
2. 将 Shizuku+ 加入“受保护应用”“永不休眠”“允许后台运行”等列表。
3. 在三星设备上关闭自动拦截器或同类限制功能。

如果你不想接收重启提醒，可以在 Watchdog 通知中关闭提醒。

## 应用管理

### 应用显示“需要 Shizuku+”并变灰

该应用使用 Shizuku+ 独有的 Plus API。当 Plus API 层被关闭时会显示此标记。请在“设置 -> Shizuku+ 功能”中启用相关能力。

### 长按应用没有反应或选项很少

长按动作可以在“设置 -> 应用管理”中分别配置。如果所有长按动作都被关闭，长按会被静默消费。请启用需要的动作，例如打开应用、应用信息、切换权限、隐藏、冻结/解冻等。

## 活动日志

### 活动日志在哪里

路径是“设置 -> 活动日志”。它会记录权限授权/撤销、长按动作、冻结/解冻操作、服务启动/停止等事件。日志保留时间可配置，默认 30 天。

### 活动日志为空

活动日志需要先在设置中启用。启用后，只会记录之后发生的事件。

## 设备兼容性

### Shizuku+ 支持 Android 14+ / One UI 8+ 吗

支持。Shizuku+ 专门面向三星 One UI 和 Android 14+ 的限制做了增强。Overlay Manager Plus 可以绕过这些版本中更严格的覆盖管理限制。

### 支持安全文件夹吗

支持。Shizuku+ 提供跨用户 Binder 共享能力，可以服务运行在安全文件夹等用户配置文件中的应用。
