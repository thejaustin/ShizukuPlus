# 自动化应用控制 Shizuku+

Shizuku+ 提供 Locale 兼容插件，Tasker、MacroDroid 等自动化应用可以通过它启动或停止 Shizuku+ 服务，也可以把“Shizuku+ 是否正在运行”作为条件使用。

## 支持的动作

自动化应用添加 Shizuku+ 插件动作时，应用会让你选择：

- 启动 Shizuku+ 服务
- 停止 Shizuku+ 服务

内部动作值分别是 `start` 和 `stop`，由 Locale 标准的 `FIRE_SETTING` 广播触发。

## 启动动作的限制

启动动作会复用 Shizuku+ 最近一次的启动方式：

- 如果最近使用 Root 启动，会尝试 Root 启动。
- 如果最近使用 ADB/无线调试启动，会尝试后台 ADB 启动。
- 如果没有可用的历史启动方式，后台自动化启动不会强行打开交互式配对流程。

ADB 后台启动仍然需要相关权限和环境满足要求，例如无线调试可用、端口可发现，或已保存的端口仍可连接。开机自启动所需的 `WRITE_SECURE_SETTINGS` 权限也适用于相关后台流程。

## 停止动作

停止动作会请求正在运行的 Shizuku 服务退出，并把状态机切换为停止中。如果服务本来没有运行，动作会直接结束。

## 条件查询

Locale 兼容应用也可以查询 Shizuku+ 当前是否正在运行：

- 运行中：返回条件满足。
- 未运行：返回条件不满足。

这个查询是同步完成的，不会进行网络、ADB 或 Root 操作，因此适合作为自动化规则条件。

## 常见用途

- 连接到指定 Wi-Fi 后自动启动 Shizuku+。
- 离开工作配置或断开电源后停止服务。
- 在执行需要权限的 Tasker/MacroDroid 任务前，先检查 Shizuku+ 是否运行。
- 配合 Watchdog 和开机启动，让服务在可控条件下保持可用。

如果自动化动作没有生效，请先手动打开 Shizuku+，确认服务能按当前启动方式正常启动，再检查自动化应用是否允许后台运行。
